# Automated Cross-OS Test Rig (Tier 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the machine-checkable rows of `docs/testing.md` on demand against an Ubuntu VM and a Windows VM, and report each row as passed, failed, skipped or inconclusive with its evidence.

**Architecture:** Shell owns VM lifecycle, because `virsh` and `virt-install` are command-line tools. Two Rust crates own everything that can lie: `pheme-probe` runs inside the VMs and emits input on one and records it on the other, and `pheme-testrig` runs on the host and turns observations into verdicts and a report. Assertions read the operating system, never pheme's own `--stats`.

**Tech Stack:** libvirt/QEMU/KVM, `virt-install` 5.1.0 with `--cloud-init` and `--tpm`, `swtpm`, OVMF, `xorriso`, OpenSSH, Rust (workspace), `evdev` on Linux, `SetWindowsHookEx` on Windows.

**Spec:** `docs/superpowers/specs/2026-09-30-test-rig-design.md`

**Deliberate refinement of spec §4.** The spec's component table puts the
runner in shell. This plan puts the runner's orchestration, verdict and
report logic in a Rust crate (`crates/pheme-testrig`), with `testrig/run` as
a thin wrapper that calls it. The reason is the spec's own §13: a rig that
cannot be shown to fail is worthless, and shell has no unit tests. Verdict
logic is exactly where a rig lies, so it goes where it can be tested. VM
provisioning stays in shell, as the spec says, because it is one-shot and
observable.

## Global Constraints

Every task's requirements implicitly include these. Values are copied from the spec.

- **Verdicts read the operating system, not pheme's `--stats`.** `--stats` output is collected as supporting evidence and never as the criterion.
- **No fixed `sleep` anywhere.** Poll for a condition against a deadline.
- **Four verdicts, all first class:** `PASS`, `FAIL`, `SKIPPED`, `INCONCLUSIVE`. A row that was not run appears with its reason and is never silently omitted. `SKIPPED` and `INCONCLUSIVE` are never rendered as a pass.
- **Infrastructure failure is not product failure.** SSH timeouts, a VM that will not boot, a missing network: affected rows become `INCONCLUSIVE` with an infrastructure reason and the report says the run hit a rig error. Never `FAIL`.
- **Deploy installs real packages** — the `.deb` on Ubuntu, the `.exe` installer on Windows. Never loose binaries.
- **`pheme-probe` and `pheme-testrig` are excluded from the `.deb` and the `.rpm`.** They are test equipment, not product.
- **The Windows VM's interactive user is a standard, non-administrator account.** Row F7 asserts the installer needs no elevation; an administrator account would pass it for the wrong reason.
- **One libvirt NAT network dedicated to the rig,** separate from `default`. Both VMs on one layer-2 segment, because mDNS is multicast.
- **The rig's SSH key is generated into `testrig/` and git-ignored.** Never the developer's own key.
- **Every row names, in a comment beside it, the mutation that would make it fail.**
- **VMs shut down after a run** unless `--keep` is passed.
- **`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` stay green.** CI runs all three on `ubuntu-latest` and `windows-latest`.
- **`Cargo.lock` is committed with any manifest change.**
- **Every file and commit message in the repo is in English.**

## Review Focus

Five ways this rig can report something false. Each line names the task whose tests pin it.

1. **A row passes on the previous run's leftovers** because the snapshot revert silently failed — the run continues against a dirty VM. Pinned in Task 4: the revert is verified to have happened before any row runs.
2. **SSH answers before the desktop session exists,** so input capture has no display and product rows fail for an infrastructure reason. Pinned in Task 4: readiness means a usable graphical session, not an open TCP port.
3. **The probe pair does not work at all** — emitted events never reach the recorder even locally — and every row fails, blaming pheme. Pinned in Task 6: a loopback self-check emits and records on one machine with pheme absent, and must pass before any cross-machine row is judged.
4. **The runner dies mid-run and prints a short table,** which reads as "the missing rows were fine". Pinned in Task 7: the report is written even on abort, with unreached rows as `SKIPPED("run aborted")`.
5. **Two runs overlap** and fight over the same VMs and network, producing a mixture of both. Pinned in Task 1: a lock, and a clear refusal rather than a corrupted run.

- [ ] **Step 1: Write the failing test for `wait_until`**

`wait_until` is the whole reason there are no sleeps in this rig, so it is
the one shell function with its own test.

Create `testrig/lib_test.sh`:

```sh
#!/bin/sh
# Tests for testrig/lib.sh. Run: sh testrig/lib_test.sh
set -eu
cd "$(dirname "$0")"
. ./lib.sh

fail=0
check() {
    if [ "$2" = "$3" ]; then echo "ok   $1"; else echo "FAIL $1: want $3, got $2"; fail=1; fi
}

# A condition that is already true returns at once.
wait_until 5 "true immediately" true
check "already-true returns 0" "$?" "0"

# A condition that never becomes true returns non-zero, and does so *before*
# twice the deadline -- a wait_until that ignored its deadline would hang the
# whole rig, which is the failure this test exists for.
start=$(date +%s)
if wait_until 2 "never true" false; then rc=0; else rc=1; fi
elapsed=$(( $(date +%s) - start ))
check "never-true returns 1" "$rc" "1"
if [ "$elapsed" -le 4 ]; then echo "ok   respects the deadline ($elapsed s)"; else
    echo "FAIL deadline ignored: $elapsed s for a 2 s deadline"; fail=1; fi

# A condition that becomes true partway through is noticed.
marker=$(mktemp)
rm -f "$marker"
( sleep 1; touch "$marker" ) &
wait_until 5 "marker appears" test -f "$marker"
check "eventually-true returns 0" "$?" "0"
rm -f "$marker"

exit "$fail"
```

- [ ] **Step 4: Write `lib.sh`**

```sh
# Shared helpers. Sourced, never executed.
# shellcheck shell=sh

log() { printf '%s  %s\n' "$(date +%H:%M:%S)" "$*" >&2; }
die() { printf 'rig error: %s\n' "$*" >&2; exit 1; }

# wait_until <deadline_seconds> <description> <command...>
#
# Polls the command until it succeeds or the deadline passes. Returns 0 on
# success, 1 on timeout.
#
# This exists because there is no `sleep` in this rig. A fixed wait either
# flakes under load or -- worse -- passes on an idle machine while proving
# nothing, which is a defect this project has already shipped once in a
# sub-project 7 test. Every wait in the rig goes through here so that the
# deadline is always explicit and always reported.
wait_until() {
    _deadline=$1; _what=$2; shift 2
    _end=$(( $(date +%s) + _deadline ))
    while :; do
        if "$@" >/dev/null 2>&1; then return 0; fi
        if [ "$(date +%s)" -ge "$_end" ]; then
            log "timed out after ${_deadline}s waiting for: $_what"
            return 1
        fi
        sleep 1   # the poll interval, not a guess at how long the work takes
    done
}

# Only one run at a time. Two overlapping runs would fight over the same
# domains and the same network and produce a report mixing both, which is
# worse than refusing.
rig_lock() {
    mkdir -p "$RIG_STATE"
    if ! mkdir "$RIG_STATE/lock" 2>/dev/null; then
        die "another rig run holds $RIG_STATE/lock; remove it if no run is active"
    fi
    echo $$ > "$RIG_STATE/lock/pid"
}
rig_unlock() { rm -rf "$RIG_STATE/lock"; }

# ssh into a rig VM by IP, with the rig's own key and no host-key prompt:
# these are throwaway machines rebuilt from snapshots, so a changing host key
# is expected rather than suspicious.
rig_ssh() {
    _ip=$1; _user=$2; shift 2
    ssh -i "$RIG_SSH_KEY" \
        -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
        -o LogLevel=ERROR -o ConnectTimeout=5 \
        "$_user@$_ip" "$@"
}
```

- [ ] **Step 6: Write `net.sh`**

```sh
#!/bin/sh
# Create or destroy the rig's libvirt network.
# Usage: net.sh up | down | status
set -eu
cd "$(dirname "$0")"
. ./rig.conf
. ./lib.sh

VIRSH="virsh -c qemu:///system"

case "${1:-}" in
up)
    if $VIRSH net-info "$RIG_NET" >/dev/null 2>&1; then
        log "network $RIG_NET already defined"
    else
        _gw=$(echo "$RIG_NET_CIDR" | sed 's|0/24|1|')
        cat > "$RIG_STATE/net.xml" <<XML
<network>
  <name>$RIG_NET</name>
  <forward mode='nat'/>
  <bridge stp='on' delay='0'/>
  <ip address='$_gw' netmask='255.255.255.0'>
    <dhcp><range start='$(echo "$RIG_NET_CIDR" | sed 's|0/24|50|')'
                 end='$(echo "$RIG_NET_CIDR" | sed 's|0/24|99|')'/></dhcp>
  </ip>
</network>
XML
        $VIRSH net-define "$RIG_STATE/net.xml"
    fi
    $VIRSH net-start "$RIG_NET" 2>/dev/null || true
    wait_until 30 "network $RIG_NET active" \
        sh -c "$VIRSH net-info $RIG_NET | grep -q 'Active:.*yes'" \
        || die "network $RIG_NET did not become active"
    log "network $RIG_NET up"
    ;;
down)
    $VIRSH net-destroy "$RIG_NET" 2>/dev/null || true
    $VIRSH net-undefine "$RIG_NET" 2>/dev/null || true
    log "network $RIG_NET down"
    ;;
status) $VIRSH net-info "$RIG_NET" ;;
*) die "usage: net.sh up|down|status" ;;
esac
```

- [ ] **Step 1: Add `rig_vm_ip` to `lib.sh`**

```sh
# The guest's IPv4 address, from the DHCP lease libvirt handed it. Printed on
# stdout; empty and non-zero if the guest has no lease yet, which is what
# makes it usable as a wait_until condition.
rig_vm_ip() {
    virsh -c qemu:///system domifaddr "$1" 2>/dev/null \
        | awk '/ipv4/ {sub("/.*","",$4); print $4; found=1} END {exit !found}'
}
```

- [ ] **Step 2: Write `provision-ubuntu.sh`**

Autologin is not a convenience here. pheme's input capture needs a live
graphical session, and a VM sitting at a login screen has none — so rows
would fail for an infrastructure reason while looking like product failures.
That is Review Focus 2, and this is half its fix; Task 4 is the other half.

```sh
#!/bin/sh
# Build the Ubuntu 24.04 Desktop VM. Idempotent: an existing domain is left
# alone unless --rebuild is passed.
#
# Built from the cloud image plus cloud-init rather than the desktop ISO with
# autoinstall: cloud-init is a documented unattended path, whereas driving the
# desktop installer means screen-scraping. `apt install ubuntu-desktop` on top
# gives the same GNOME-on-Wayland session a person would have, and an X11
# session is selectable from the same VM for the W rows.
set -eu
cd "$(dirname "$0")"
. ./rig.conf
. ./lib.sh

VIRSH="virsh -c qemu:///system"
IMG_URL=https://cloud-images.ubuntu.com/releases/24.04/release/ubuntu-24.04-server-cloudimg-amd64.img
BASE="$RIG_STATE/ubuntu-base.img"
DISK="$RIG_STATE/$UBUNTU_VM.qcow2"

if [ "${1:-}" = "--rebuild" ]; then
    $VIRSH destroy "$UBUNTU_VM" 2>/dev/null || true
    $VIRSH undefine "$UBUNTU_VM" --nvram --remove-all-storage 2>/dev/null || true
fi
if $VIRSH dominfo "$UBUNTU_VM" >/dev/null 2>&1; then
    log "$UBUNTU_VM already exists; pass --rebuild to replace it"
    exit 0
fi

mkdir -p "$RIG_STATE"
[ -f "$RIG_SSH_KEY" ] || ssh-keygen -t ed25519 -N '' -C pheme-rig -f "$RIG_SSH_KEY"
[ -f "$BASE" ] || { log "downloading the Ubuntu cloud image"; curl -fL -o "$BASE" "$IMG_URL"; }

cp "$BASE" "$DISK"
qemu-img resize "$DISK" "${UBUNTU_DISK_GB}G"

cat > "$RIG_STATE/ubuntu-user-data" <<YAML
#cloud-config
hostname: pheme-ubuntu
users:
  - name: rig
    groups: [sudo, input]
    shell: /bin/bash
    sudo: ["ALL=(ALL) NOPASSWD:ALL"]
    ssh_authorized_keys:
      - $(cat "$RIG_SSH_KEY.pub")
package_update: true
packages: [ubuntu-desktop-minimal, pipewire, pipewire-pulse, wireplumber]
runcmd:
  # Autologin: pheme's input capture needs a live graphical session, and a VM
  # parked at a login screen has none. Without this, product rows fail for an
  # infrastructure reason.
  - |
    install -d /etc/gdm3
    printf '[daemon]\nAutomaticLoginEnable=true\nAutomaticLogin=rig\n' \
      > /etc/gdm3/custom.conf
  - systemctl set-default graphical.target
  # A marker the runner polls for. Written last, so its presence means every
  # step above finished -- cloud-init's own status is not enough, because the
  # desktop packages are what the rows need and they install late.
  - touch /var/lib/cloud/pheme-rig-ready
YAML

log "creating $UBUNTU_VM (installing the desktop takes several minutes)"
virt-install \
  --connect qemu:///system \
  --name "$UBUNTU_VM" \
  --memory "$UBUNTU_RAM_MB" --vcpus 2 \
  --disk "path=$DISK,format=qcow2" \
  --os-variant ubuntu24.04 \
  --network "network=$RIG_NET,model=virtio" \
  --graphics spice --video virtio \
  --cloud-init "user-data=$RIG_STATE/ubuntu-user-data" \
  --import --noautoconsole

wait_until 120 "$UBUNTU_VM to get a DHCP lease" rig_vm_ip "$UBUNTU_VM" \
    || die "$UBUNTU_VM never got an address"
IP=$(rig_vm_ip "$UBUNTU_VM")
log "$UBUNTU_VM is at $IP"

wait_until 1800 "$UBUNTU_VM cloud-init to finish the desktop install" \
    rig_ssh "$IP" rig test -f /var/lib/cloud/pheme-rig-ready \
    || die "$UBUNTU_VM never finished provisioning; check: rig_ssh $IP rig sudo cloud-init status --long"

log "$UBUNTU_VM provisioned"
```

- [ ] **Step 1: Write `testrig/windows/autounattend.xml`**

Two things in this file are load-bearing and easy to get subtly wrong.

The interactive account is a **standard user**, not an administrator. Row F7
asserts the installer needs no elevation; run as an administrator, that row
passes whatever the installer does, which is the "test that cannot fail"
defect this project has shipped before.

OpenSSH Server is enabled through `FirstLogonCommands`, and the rig's public
key goes to `administrators_authorized_keys` **and** the user's own
`authorized_keys` — Windows OpenSSH ignores a user file for accounts in the
Administrators group, and this account is deliberately not one, so the user
file is the one that matters here.

```sh
# Build the Windows 11 VM from the Enterprise Evaluation ISO.

# UEFI and an emulated TPM 2.0 are not options: Windows 11 Setup refuses a

  Get it from: https://www.microsoft.com/en-us/evalcenter/download-windows-11-enterprise
  Then: WINDOWS_ISO=/path/to/it.iso sh testrig/provision-windows.sh"

[ -f "$RIG_SSH_KEY" ] || ssh-keygen -t ed25519 -N '' -C pheme-rig -f "$RIG_SSH_KEY"

  --connect qemu:///system \
  --name "$WINDOWS_VM" \
  --memory "$WINDOWS_RAM_MB" --vcpus 4 \
  --cpu host-passthrough \
  --disk "path=$DISK,format=qcow2,bus=sata" \
  --cdrom "$ISO" \
  --disk "path=$SEED,device=cdrom" \
  --os-variant win11 \
  --network "network=$RIG_NET,model=e1000e" \
  --graphics spice --video qxl \
  --boot uefi \
  --tpm backend.type=emulator,backend.version=2.0,model=tpm-crb \
```

```sh
#!/bin/sh
# Create or revert each VM's clean snapshot.
# Usage: snapshot.sh create <domain> | revert <domain>
#
# The revert is what makes a second run mean anything. Rows install and remove
# packages, write trusted.toml during pairing and config.toml on first start.
# Without reverting, a later run can pass on the previous run's leftovers
# rather than on the code.
set -eu
cd "$(dirname "$0")"
. ./rig.conf
. ./lib.sh

VIRSH="virsh -c qemu:///system"
SNAP=clean
DOM="${2:?usage: snapshot.sh create|revert <domain>}"

case "${1:-}" in
create)
    $VIRSH destroy "$DOM" 2>/dev/null || true
    wait_until 60 "$DOM to stop" sh -c "$VIRSH domstate $DOM | grep -q 'shut off'" \
        || die "$DOM would not stop; cannot snapshot a running domain safely"
    $VIRSH snapshot-delete "$DOM" --snapshotname "$SNAP" 2>/dev/null || true
    $VIRSH snapshot-create-as "$DOM" --name "$SNAP" \
        --description "clean state, taken after provisioning" --atomic
    log "$DOM snapshot '$SNAP' created"
    ;;
revert)
    $VIRSH snapshot-info "$DOM" --snapshotname "$SNAP" >/dev/null 2>&1 \
        || die "$DOM has no '$SNAP' snapshot; run: snapshot.sh create $DOM"
    $VIRSH destroy "$DOM" 2>/dev/null || true
    $VIRSH snapshot-revert "$DOM" --snapshotname "$SNAP" --force
    log "$DOM reverted to '$SNAP'"
    ;;
*) die "usage: snapshot.sh create|revert <domain>" ;;
esac
```

- [ ] **Step 2: Add readiness and canary helpers to `lib.sh`**

```sh
# True when the guest has a usable graphical session -- not merely an open SSH
# port. pheme's input capture needs a live session, so a VM sitting at a login
# screen would fail product rows for an infrastructure reason. Review Focus 2.
rig_session_ready() {
    _ip=$1; _os=$2
    case "$_os" in
    linux)
        rig_ssh "$_ip" rig 'test -n "$(loginctl show-user rig -p Display --value)"'
        ;;
    windows)
        # A marker written by the first-logon script, plus an interactive
        # session actually present now -- the marker alone survives a reboot
        # into a locked screen.
        rig_ssh "$_ip" rig \
          'if ((Test-Path C:\Users\Public\pheme-rig-ready) -and
                (Get-Process -Name explorer -ErrorAction SilentlyContinue)) { exit 0 } else { exit 1 }'
        ;;
    *) return 1 ;;
    esac
}

# Start a domain and wait until it is genuinely usable. Prints the IP.
rig_boot() {
    _dom=$1; _os=$2
    virsh -c qemu:///system start "$_dom" >/dev/null 2>&1 || true
    wait_until 180 "$_dom to get an address" rig_vm_ip "$_dom" \
        || { log "rig error: $_dom never got an address"; return 1; }
    _ip=$(rig_vm_ip "$_dom")
    wait_until 300 "$_dom to reach a usable session" rig_session_ready "$_ip" "$_os" \
        || { log "rig error: $_dom has no graphical session"; return 1; }
    printf '%s\n' "$_ip"
}

# The canary proves a revert actually happened. The runner drops it at the end
# of every run; after the next revert it must be gone. A snapshot-revert that
# silently did nothing would otherwise leave the rig running rows against the
# previous run's leftovers and reporting the result as fact. Review Focus 1.

rig_canary_absent() { ! rig_ssh "$1" "$2" 'test -f /tmp/pheme-rig-canary 2>/dev/null || Test-Path $env:TEMP\pheme-rig-canary'; }
```

- [ ] **Step 3: Write the minimal implementation**

Above the test module in `gesture.rs`:

```rust
//! Gestures a row asks for, and their expansion into individual events.
//!
//! Pure on purpose: this is the half of the probe that decides *what* to send,
//! and it is unit-tested, while the half that talks to uinput or SendInput is
//! not testable off a real machine. Keeping them apart means a row's intent
//! can be checked without a VM.

use anyhow::{bail, Result};
use pheme_proto::KeyCode;

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Gesture {
    MoveRel { dx: i32, dy: i32 },
    Type(String),
    Hold(KeyCode),
    Release(KeyCode),
    Wheel(i32),
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ProbeEvent {
    MoveRel { dx: i32, dy: i32 },
    KeyDown(KeyCode),
    KeyUp(KeyCode),
    Wheel(i32),
}

/// Expands gestures into the events to send, in order.
pub fn expand(gestures: &[Gesture]) -> Vec<ProbeEvent> {
    let mut out = Vec::new();
    for g in gestures {
        match g {
            Gesture::MoveRel { dx, dy } => out.push(ProbeEvent::MoveRel { dx: *dx, dy: *dy }),
            Gesture::Wheel(n) => out.push(ProbeEvent::Wheel(*n)),
            // Hold and Release are unbalanced by design: row S5 holds a
            // modifier on one machine and releases it on the other.
            Gesture::Hold(k) => out.push(ProbeEvent::KeyDown(*k)),
            Gesture::Release(k) => out.push(ProbeEvent::KeyUp(*k)),
            Gesture::Type(text) => {
                for ch in text.chars() {
                    let (key, shift) = key_for_char(ch).expect("caller validated the text");
                    if shift {
                        out.push(ProbeEvent::KeyDown(KeyCode::LEFT_SHIFT));
                    }
                    out.push(ProbeEvent::KeyDown(key));
                    out.push(ProbeEvent::KeyUp(key));
                    if shift {
                        out.push(ProbeEvent::KeyUp(KeyCode::LEFT_SHIFT));
                    }
                }
            }
        }
    }
    out
}

/// Parses the gesture string the runner sends over ssh, e.g.
/// `"move 2000 0; type Hi; hold LeftShift"`.
pub fn parse(spec: &str) -> Result<Vec<Gesture>> {
    let mut out = Vec::new();
    for part in spec.split(';').map(str::trim).filter(|s| !s.is_empty()) {
        let mut words = part.split_whitespace();
        let verb = words.next().unwrap_or("");
        match verb {
            "move" => {
                let dx = words.next().unwrap_or("").parse()?;
                let dy = words.next().unwrap_or("").parse()?;
                out.push(Gesture::MoveRel { dx, dy });
            }

            // Never silently ignored: a typo in a row's gesture would become
            // a no-op that still reported PASS.
            other => bail!("unknown gesture verb {other:?} in {part:?}"),
        }
    }
    Ok(out)
}
```

```rust
//! Turning a recorded event stream into the numbers a row asserts on.
//!
//! Pure, and deliberately separate from the platform recorders: this is where
//! "nothing was left held" is decided, and that decision is too important to
//! live somewhere only a VM can reach.

use std::collections::BTreeSet;

use serde::{Deserialize, Serialize};

use crate::gesture::ProbeEvent;
use pheme_proto::KeyCode;

#[derive(Debug, Default, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Tally {
    pub downs: u32,
    pub ups: u32,
    pub motion: u32,
    pub wheel: u32,
    /// Keys still down when recording stopped. Tracked as a set of keys, not
    /// inferred from `downs != ups`: a stream with equal counts across two
    /// different keys can still leave one held.
    pub held: Vec<KeyCode>,
    /// Key-ups with no matching down. Non-zero means the recording started
    /// mid-gesture, so the other numbers describe a fragment.
    pub unmatched_ups: u32,
}

pub fn tally(events: &[ProbeEvent]) -> Tally {
    let mut t = Tally::default();
    let mut down: BTreeSet<KeyCode> = BTreeSet::new();
    for e in events {
        match e {
            ProbeEvent::KeyDown(k) => {
                t.downs += 1;
                down.insert(*k);
            }
            ProbeEvent::KeyUp(k) => {
                t.ups += 1;
                if !down.remove(k) {
                    t.unmatched_ups += 1;
                }
            }
            ProbeEvent::MoveRel { .. } => t.motion += 1,
            ProbeEvent::Wheel(_) => t.wheel += 1,
        }
    }
    t.held = down.into_iter().collect();
    t
}
```

`KeyCode` already derives `Ord`, `Hash`, `Serialize` and `Deserialize`
(`crates/pheme-proto/src/lib.rs:64`), so `BTreeSet<KeyCode>` and the serialized
`Tally` both work with no change to a shipped type.

```rust
// verdict.rs
//! The four verdicts, and the rules that keep a report honest.

use serde::Serialize;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize)]
#[serde(rename_all = "UPPERCASE")]
pub enum Verdict {
    Pass,
    Fail,
    /// Not attempted. Always carries a reason.
    Skipped,
    /// Attempted, but the criterion could not be evaluated.
    Inconclusive,
    /// The row itself is untrustworthy -- it passed with pheme switched off.
    Broken,
}

impl Verdict {
    /// Infrastructure failure is not product failure. An SSH timeout or a dead
    /// libvirt network says nothing about pheme, and a report that blames
    /// pheme for an unstarted network is worse than no report.
    pub fn from_rig_error(_reason: &str) -> Verdict {
        Verdict::Inconclusive
    }
}

#[derive(Debug, Clone, Serialize)]
pub struct RowResult {
    pub id: String,
    pub what: String,
    pub verdict: Verdict,
    pub evidence: String,
}
```

```rust
// report.rs -- above the tests
use crate::verdict::{RowResult, Verdict};

/// Every planned row appears in the output. Rows the run never reached become
/// SKIPPED with the reason, so a run that died partway cannot read as a short
/// all-green table.
pub fn finalise(
    planned: &[&str],
    done: Vec<RowResult>,
    aborted: Option<&str>,
) -> Vec<RowResult> {
    let mut out = done;
    for id in planned {
        if out.iter().any(|r| r.id == *id) {
            continue;
        }
        let reason = match aborted {
            Some(why) => format!("run aborted: {why}"),
            None => "run aborted before this row".to_string(),
        };
        out.push(RowResult {
            id: (*id).to_string(),
            what: String::new(),
            verdict: Verdict::Skipped,
            evidence: reason,
        });
    }
    out.sort_by(|a, b| a.id.cmp(&b.id));
    out
}

fn verdict_name(v: Verdict) -> &'static str {
    match v {
        Verdict::Pass => "PASS",
        Verdict::Fail => "FAIL",
        Verdict::Skipped => "SKIPPED",
        Verdict::Inconclusive => "INCONCLUSIVE",
        Verdict::Broken => "BROKEN",
    }
}

pub fn render_table(rows: &[RowResult]) -> String {
    let w_id = rows.iter().map(|r| r.id.len()).max().unwrap_or(3).max(3);
    let w_what = rows.iter().map(|r| r.what.len()).max().unwrap_or(4).max(4);
    let mut out = format!(
        "{:<w_id$}  {:<w_what$}  {:<12}  {}\n",
        "ROW", "WHAT", "VERDICT", "EVIDENCE"
    );
    for r in rows {
        out.push_str(&format!(
            "{:<w_id$}  {:<w_what$}  {:<12}  {}\n",
            r.id,
            r.what,
            verdict_name(r.verdict),
            r.evidence
        ));
    }
    out
}

pub fn render_json(rows: &[RowResult]) -> String {
    serde_json::json!({ "rows": rows }).to_string()
}

/// Only Fail and Broken make a run unsuccessful. Skipped must not: rows
/// E1-E10 are permanently skipped, and an always-non-zero exit trains
/// everybody to ignore it.
pub fn exit_code(rows: &[RowResult]) -> i32 {
    let bad = rows
        .iter()
        .filter(|r| matches!(r.verdict, Verdict::Fail | Verdict::Broken))
        .count();
    i32::from(bad > 0)
}
```

```rust
/// Reinterprets a row's verdict for a negative-control run, where pheme was
/// deliberately never started. A row that failed did its job, so it reads as
/// PASS here; a row that passed cannot have been measuring pheme, so it reads
/// as BROKEN.
pub fn under_negative_control(v: Verdict) -> Verdict {
    match v {
        Verdict::Pass => Verdict::Broken,
        Verdict::Fail => Verdict::Pass,
        other => other,
    }
}
```
